# Agent Lifecycle Management 改修案の検討報告書

## 1. はじめに
本ドキュメントは、`docs/design/agent-lifecycle-management.md` で提案されたエージェントのライフサイクル管理の刷新案について、現状のコードベースとの整合性および設計の妥当性を中立的な視点から検討した結果をまとめたものである。

## 2. 現状の問題分析の妥当性
提案書で指摘されている以下の問題点は、実際のコード（`AutoExecutionCoordinator.ts`, `SpecManagerService.ts`, `AgentRecordService.ts`）において存在することを確認した。

| 指摘事項 | コードベースでの確認結果 |
| :--- | :--- |
| **タイムアウト時の不完全なクリーンアップ** | `AutoExecutionCoordinator` はタイムアウトを検知するが、プロセスを明示的に kill する `stopAgent` を呼び出していない。 |
| **状態とプロセスの分離** | 実行状態（Coordinator）とプロセスハンドル（SpecManager）が別々の Map で管理されており、一方の更新が他方に波及しないケースがある。 |
| **PID 再利用による誤判定** | `AgentRecordService` の生存確認は PID の存在チェック（`signal 0`）のみであり、プロセス開始時刻による厳密な照合が行われていない。 |
| **責務の分散** | ライフサイクル管理のロジックが Coordinator, Service, IPC Handlers に分散しており、一貫した制御が困難。 |

## 3. 改修案（理想形）の評価

### 3.1 アーキテクチャの妥当性
提案されている `AgentLifecycleManager` への一元化は、**Single Source of Truth (SSOT)** の原則に基づいた適切な設計である。エージェントの「物理的実体（ChildProcess）」と「論理的状態（AgentState）」を `AgentHandle` で統合管理することで、状態の乖離を防ぐことができる。

### 3.2 監視戦略の評価
以下の 3 層による監視は、エージェントプロセスの制御不能な放置（ゾンビ化）を防ぐために極めて堅牢なアプローチである。
1.  **イベント駆動**: `exit` イベントによる即時反応
2.  **アクティビティ監視**: Coordinator レベルでの論理タイムアウト
3.  **Watchdog (ヘルスチェック)**: 定期的な PID + 開始時刻のポーリングによる孤児プロセス検出

### 3.3 PID 再利用対策の評価
`processStartTime` を `AgentRecord` に含める設計は、OS レベルでの同一性確認として標準的かつ信頼性が高い。これにより、アプリの再起動を跨いだ状態同期の正確性が劇的に向上する。

## 4. 実装計画とリスク

### 4.1 段階的実装の妥当性
Phase 0 から Phase 4 までの計画は、データ構造の変更、サービスの抽出、高度な機能（再接続）の順に整理されており、リスクを抑えた移行が可能である。

### 4.2 最小限の修正案（Phase 5）の重要性
理想形への完全移行には相応の工数が必要だが、「5.1 タイムアウト時のプロセス停止」のような最小限の修正を優先的に適用することで、現在発生しているゾンビプロセスの問題を即座に軽減できる。これはプロダクトの品質向上において非常に重要である。

## 5. 結論と提言
`docs/design/agent-lifecycle-management.md` の改修案は、現状の課題を的確に捉え、アーキテクチャとして整合性の取れた解決策を提示している。

**提言:**
1.  **Phase 5（最小限の修正）の即時実施**: `autoExecutionHandlers.ts` または `AutoExecutionCoordinator` に、タイムアウトエラー時に `stopAgent` を呼び出すロジックを追加することを推奨する。
2.  **Phase 0（AgentRecord の拡張）の開始**: プロセス開始時刻の記録を開始することで、次フェーズ以降の基盤を整えるべきである。
3.  **OS 抽象化の考慮**: `ps` コマンドによる開始時刻取得は、将来的な Windows 対応を見据えて、OS ごとの差異を吸収できるユーティリティとして実装することを推奨する。

---
**判定: 承認（設計・計画ともに極めて妥当）**
