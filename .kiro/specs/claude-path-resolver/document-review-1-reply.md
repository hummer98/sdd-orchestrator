## Response to Warnings

### W-1: タイムアウト値の不整合

**Issue**: research.mdでは5秒タイムアウトの例示があるが、design.mdやtasks.mdではタイムアウト値が明示されていない。

**Judgment**: **Fix Required** ✅

**Evidence**:
research.md の Implementation Guidance セクションで明確に `timeout: 5000` が定義されている:

```typescript
const { stdout } = await execAsync(`${shell} -l -c 'which claude'`, {
  timeout: 5000, // 5秒タイムアウト
});
```

しかし、design.md の Error Handling セクションでは「数秒」「数百ミリ秒」と曖昧な表現にとどまっている。実装時の判断を統一するため、design.mdに具体的なタイムアウト値を追記すべき。

**Action Items**:
- design.md の Error Handling セクションにタイムアウト値 5000ms を明示

---

### W-2: シェルパスの特殊文字対応

**Issue**: `$SHELL` に空白や特殊文字が含まれる可能性を考慮し、エスケープ処理の必要性を検討。

**Judgment**: **No Fix Needed** ❌

**Evidence**:
1. `$SHELL` 環境変数はOSが管理するシェルパスであり、空白や特殊文字を含むことは極めて稀
2. POSIX標準のシェルパス（`/bin/bash`, `/bin/zsh`, `/bin/sh`等）にはスペースを含まない
3. research.md の実装例では、シングルクォートで囲んでいるのは `which claude` コマンド部分であり、`$SHELL` 変数自体はシェルによって正しく展開される
4. 同様のパターンを使用している既存ツール（nvm, rbenv等）でもエスケープ処理は行われていない

過剰な防御的コーディングは YAGNI 原則に反する。実際に問題が報告された場合に対応すればよい。

---

### W-3: Windows環境での動作が未定義

**Issue**: 本設計はmacOS/Linux環境を前提としており、Windows環境での動作が未定義。

**Judgment**: **Fix Required** ✅

**Evidence**:
1. SDD OrchestratorはElectronアプリであり、開発環境はmacOS/Linuxが主要ターゲット
2. CLAUDE.mdの開発コマンドやproduct.mdの文脈からも、Windows対応は現時点で想定されていない
3. `$SHELL` 環境変数やログインシェルの概念はWindowsでは異なる仕組みであり、本設計の前提が成り立たない

requirements.md の Out of Scope に Windows 対応を明記することで、将来の混乱を防ぐ。

**Action Items**:
- requirements.md の Out of Scope に「Windows環境のサポート（macOS/Linuxのみ対象）」を追加
