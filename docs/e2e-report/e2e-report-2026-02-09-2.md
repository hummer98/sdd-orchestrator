## エラー詳細

### Electron E2E - 主要な失敗パターン

#### 1. auto-execution 関連 (electronAPI.updateSpecJson / autoExecutionReset 未定義)

**影響ファイル**: agent-log-streaming, auto-execution-flow, auto-execution-permissions, auto-execution-resume, auto-execution-workflow, simple-auto-execution, auto-execution-impl-phase, auto-execution-intermediate-artifacts, auto-execution-document-review, auto-execution-impl-flow, bug-auto-execution

**エラー**:
```
[E2E] setAutoExecutionPermissions: electronAPI.updateSpecJson not available
[E2E] resetAutoExecutionCoordinator error: TypeError: window.electronAPI.autoExecutionReset is not a function
```

**原因**: `electronAPI.updateSpecJson` と `electronAPI.autoExecutionReset` がRendererに公開されていない。preload/index.ts で tRPC マイグレーション後にこれらの API が削除された可能性。

#### 2. file-watcher 関連 (UI更新が検知されない)

**影響ファイル**: file-watcher-ui-update, file-watcher-root-monitoring, bugs-file-watcher, worktree-two-stage-watcher

**エラー**:
```
expect(received).toBe(expected) // Object.is equality
Expected: true
Received: false
```

**原因**: ファイルシステム変更後のUI更新タイミングがテスト待機時間内に完了しない。

#### 3. worktree 関連 (ImplFlowFrame / badge 表示)

**影響ファイル**: worktree-execution, worktree-spec-sync, impl-start-worktree, convert-spec-to-worktree

**エラー**:
```
expect(received).toBe(expected) // Object.is equality
Expected: true
Received: false
```

**原因**: Worktree関連のUI要素（ImplFlowFrame checkbox, worktree badge）が表示されない。UIコンポーネントの data-testid 変更またはレンダリング条件の変更の可能性。

#### 4. bugs-pane-integration (Bug選択後のUI連動)

**影響ファイル**: bugs-pane-integration

**エラー**:
```
- Bugsタブに切り替えできる
- "before each" hook for Bug選択時の3ペイン連動
- "before each" hook for BugArtifactEditorドキュメントタブ
- "before each" hook for BugWorkflowView5フェーズ表示
- UIレイアウト一貫性 Bug選択時のレイアウトがSpec選択時と同様の構成
- "before each" hook for フェーズ実行ボタン動作（インフラ確認）
```

**原因**: Bugsタブ切り替え後のUI要素待機でタイムアウト。`docs-tabs` data-testid が見つからない。

#### 5. agent-resume-log-display (全テスト失敗)

- should display accumulated logs in AgentLogPanel after resume

**原因**: エージェント再開機能のAPI変更または未実装。

#### 6. cloudflare-tunnel (API名変更)

- Tunnel状態変更イベントリスナーAPIが存在する

### Remote UI E2E - 主要な失敗パターン

#### 1. タイムアウト (全体の大半)

ほぼ全ての失敗テストが11.4-11.5秒のタイムアウトで失敗。

**共通エラー**:
```
Timeout 11500ms exceeded.
```

**原因**: fixture プロジェクト (`bugs-pane-test`) のWebSocket接続後にRemote UIのコンポーネントレンダリングが完了しない。Desktop Layoutのspec detail, docs-tabs, remote-tab-bugs 等のコンポーネントが表示されない。

#### 2. smartphone-spec-create.spec.ts (27件全滅)

**原因**: ダイアログUIの表示待機でタイムアウト。CreateSpecDialogの要素が表示されない。

#### 3. Desktop専用テスト (auto-execution, phase-execution, workflow-integration, remote-ui-task-progress)

**原因**: Desktop Layoutでのspec detail表示がタイムアウト。`remote-artifact-editor` 要素が表示されない。

#### 4. bug-management.spec.ts (15件失敗)

**原因**: Bugsタブへの切り替えが完了しない。Desktop/Mobile両方で `remote-tab-bugs` のクリック後にタブパネルが切り替わらない。
