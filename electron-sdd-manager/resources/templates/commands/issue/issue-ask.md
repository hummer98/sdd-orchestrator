# Issue Ask

<background_information>
- **Mission**: Execute a user-specified prompt with the GitHub Issue context loaded
- **Success Criteria**:
  - Issue context is loaded and available
  - User's prompt is executed with full Issue context
  - Results are posted as an Issue comment
- **Workflow Position**: Usable at any point in the Issue workflow
</background_information>

<environment_context>
**Current Working Directory**: The directory where this command is executed
**CRITICAL**: All file operations MUST be performed relative to the current working directory.

- Source files: All paths are relative to current directory
- Script location: `.kiro/scripts/gh-issue.sh`
</environment_context>

<instructions>
## Core Task
Load the GitHub Issue context for `$0` (issue number) and execute the user's prompt `$1`.

## Parse Arguments
- Issue number: `$0` (required)
- User prompt: `$1` (required - the instruction to execute with Issue context)

## Execution Steps

### 1. Load Issue Context
Fetch the Issue body and all comments using `gh-issue.sh`:

```bash
bash .kiro/scripts/gh-issue.sh read $0
```

Read the output carefully. This is your context for the user's request.

### 2. Execute User Prompt
With the Issue context loaded, execute the user's instruction: `$1`

The user's prompt may include tasks such as:
- Answering questions about the Issue
- Suggesting implementation approaches
- Reviewing related code
- Generating documentation
- Any other task that benefits from Issue context

### 3. Post Results to Issue
Post the execution results as an Issue comment:

```bash
bash .kiro/scripts/gh-issue.sh comment $0 "## Response

<results of the user's prompt>

---
_Generated by SDD Orchestrator_"
```

## Guidelines
- Always load the full Issue context before executing the prompt
- Respect the user's prompt as the primary instruction
- Keep the Issue comment concise but informative
</instructions>

## Tool Guidance
- Use **Bash** to run `gh-issue.sh` for Issue context and comment posting
- Use **Read**, **Glob**, **Grep** as needed based on the user's prompt
- Use **Edit**, **Write** if the user's prompt requires code changes

## Output Description
Provide output based on the user's prompt. Include:

1. **Issue Context**: Brief summary of the loaded Issue
2. **Response**: Results of executing the user's prompt
3. **Comment Posted**: Confirmation that results were posted to the Issue

## Safety & Fallback
- **Issue Not Found**: If `gh-issue.sh read` fails, verify the issue number and GitHub authentication
- **No Prompt Provided**: If `$1` is empty, ask the user what they want to do with the Issue context
- **Auth Error**: Suggest checking `GITHUB_TOKEN` or running `gh auth login`
