# 1. 初期要求

## 背景

Spec-Driven Development (SDD) のSteeringファイルは、プロジェクト知識のSSOT（Single Source of Truth）として機能する。しかし、以下の課題が認識されていた：

### 課題

1. **情報量の問題**
   - Steeringファイル群は合計114KB（約30,000トークン）
   - テキストベースのため全体像の把握が困難
   - 「膨大」または「簡略化されすぎる」の両極端

2. **認知負荷**
   - 新規参加者がプロジェクト構造を理解するのに時間がかかる
   - ファイル間の関係性が暗黙的で見えにくい
   - 重要なルール（State管理、Process Boundary等）がテキストに埋もれる

3. **既存の可視化機能との関係**
   - `docs/future-concepts/visualization.md` にdesign.md用の可視化要件が存在
   - Steering用の可視化は未定義

## ユーザー要求（原文）

> docs/future-concepts/visualization.md を雛形に以下のようなプロンプトを実験的に作成してほしいです。
>
> SpecDrivenDevelopmentのsteeringファイルを生成するプロセスではmarkdownを中心に出力されるのですが、膨大なあるいは簡略化されすぎるため、人間がアプリケーションの全体像を把握するのに苦労する状態だと認識しています。この資料で示されるようなビジュアライザのテストヘッドとして、現在存在するsteeringファイルで提供されるような情報を、人間が認知しやすいようにビジュアライズする、新しいsteeringプロンプトを考案してほしいです。

## 要求された調査項目

1. **SDDにおけるSteeringファイルの定義と目的**
   - 各ファイルの役割
   - ファイル間の関係性
   - 使用されるコンテキスト

2. **人間の認知能力に適合したビジュアライズのノウハウ**
   - 色の使い分け
   - 表現方法
   - インタラクティブ要素の動作

## 要求されたプロセス

```
調査 → プロンプト考案 → 実行 → 改善
```

## 追加要求（議論中に明確化）

ユーザーからの追加情報：

1. **対象範囲**: 判断はAI側に委ねる（統合 or 分離）
2. **ユースケース**: オンボーディング、レビュー、参照すべて
3. **優先可視化要素**:
   - アーキテクチャ
   - 状態管理
   - ワークフロー
4. **アニメーション**: 複雑かつ重要な処理にはアニメータブルなシーケンス図が有効
5. **判断の委譲**: 何をビジュアライズすべきかは調査結果から判断してほしい
