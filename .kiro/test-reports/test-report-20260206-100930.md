## 詳細分析

### カテゴリ1: electron-trpc importエラー（95件）

**影響ファイル**: `src/preload/index.test.ts` (87件), `src/main/index.test.ts` (8件)

**エラーメッセージ**:
```
file:///...node_modules/electron-trpc/dist/main.mjs:11
import { ipcMain as ee, contextBridge as re, ipcRenderer as U } from "electron";
```

**実装コード調査**:
- `src/preload/trpc.ts:11` → `import { exposeElectronTRPC } from 'electron-trpc/main'`
- `src/main/trpc/handler.ts:8` → `import { createIPCHandler } from 'electron-trpc/main'`
- これらがテスト時に実際の`electron`モジュールをインポートしようとして失敗

**根本原因**:
`src/test/setup.ts`（グローバルテストセットアップ）に`electron-trpc/main`のモックが**欠落**している。
個別テストファイル（`trpc-preload.test.ts`, `main-integration.test.ts`）には独自のモックがあり成功している。

**分類**: テスト環境バグ（グローバルモック不足）

**修正案**:
```typescript
// src/test/setup.ts に追加
vi.mock('electron-trpc/main', () => ({
  exposeElectronTRPC: vi.fn(),
  createIPCHandler: vi.fn(),
}));
```

### カテゴリ2: タイムアウト（49件）

**影響ファイル**:
- `scheduleTaskCoordinator.test.ts` (28件)
- `specManagerService.test.ts` (18件)
- `remoteAccessE2E.test.ts` (17件)
- `remoteAccessIntegration.test.ts` (8件)

**根本原因**:
1. **Vitestデフォルトタイムアウト5秒** vs テスト内の待機処理の競合
   - `specManagerService.test.ts`: `sleep 5`/`sleep 10`コマンドでプロセス終了を待機（5秒では不足）
   - `remoteAccessE2E/Integration`: WebSocket接続待機が5秒で、Vitestタイムアウトも5秒で競合
2. **vitest.config.ts** にグローバル`testTimeout`設定が未定義
3. `scheduleTaskCoordinator.test.ts`はfakeタイマー使用だが、セットアップ初期化遅延の可能性

**分類**: テスト設計/環境問題

**修正案**:
- `vitest.config.ts`にグローバルタイムアウトを追加:
  ```typescript
  test: {
    testTimeout: 30000,  // 30秒
    hookTimeout: 15000,
  }
  ```
- 個別テストでの`test.timeout`指定の見直し
