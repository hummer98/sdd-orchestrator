### W-3: e2e-plan.json永続化の明確化

**Issue**: design.mdでe2e-plan.jsonは`inspection-context/`に配置されるが、inspection終了後の扱い（保持？削除？）がTask記述に明示されていない

**Judgment**: **No Fix Needed** ❌

**Evidence**:

design.md の Physical Data Model（行805-815）:
```
.kiro/specs/{feature}/inspection-context/
├── context-summary.json        # 共通サマリー
├── requirements-result.json    # requirements-checker出力
├── design-result.json          # design-checker出力
├── code-quality-result.json    # code-quality-checker出力
├── integration-result.json     # integration-checker出力
├── e2e-plan.json              # e2e-planner出力（NEW）
└── e2e-result.json            # e2e-runner出力（NEW）
```

inspection-context/ディレクトリは既存のinspection結果ファイル（requirements-result.json, design-result.json等）と同様の扱いであり、inspection終了後も保持される。これは既存パターン（inspection-distributed）と一貫しており、暗黙的に理解可能。明示的な追記は過剰仕様となる。
