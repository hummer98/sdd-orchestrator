**Issue**: ラッパーの具体的な実装方針を確認すること（既存シグネチャ維持 vs 新しいApiClient引数追加）

**Judgment**: **No Fix Needed** ❌

**Evidence**:
既存コードを確認した結果、後方互換性は維持可能であることを確認。

**現在のElectron版 ensureLogsLoaded シグネチャ** (`renderer/stores/agentStore.ts:402`):
```typescript
ensureLogsLoaded: async (agentId: string) => {
  // ...
  await agentOperations.loadAgentLogs(agent.specId, agentId);
}
```

**呼び出し元** (`renderer/components/AgentLogPanel.tsx:23`):
```typescript
const ensureLogsLoaded = useAgentStore((state) => state.ensureLogsLoaded);
// ...

```

Design.mdのDD-003で決定した通り、Electron版Facadeは「共通版への委譲」として実装される。具体的には:

1. Electron版`renderer/stores/agentStore.ts`の`ensureLogsLoaded(agentId: string)`シグネチャは維持
2. 内部実装を`shared/stores/agentStore.ts`の`ensureLogsLoaded(apiClient, agentId)`への委譲に変更
3. apiClientはFacade内部で解決（IpcApiClientを使用）

この方針はTask 4.1に「後方互換性維持のため薄いラッパーとして残す」と既に記載されており、仕様上の曖昧さはない。
